01

Bài toán

Mọi công cụ AI đều hứa “tìm bug trong code của bạn”. Không công cụ nào nói bắt được bao nhiêu phần trăm và trượt loại lỗi nào. Không đo được vì thiếu đúng một thứ: đáp án biết trước.

Chạy agent trên một repo bất kỳ rồi đếm findings thì không biết cái nào đúng, và tuyệt nhiên không biết nó đã bỏ sót gì.

Giải pháp: tự cấy 15 lỗi vào một repo thật — mỗi lỗi một commit, message nguỵ trang để lịch sử git không lộ đáp án. Giờ có đáp án. Giờ đo được.

Repo được chọn là chatbot bán hàng Messenger từng chạy thật cho khách. Các lỗi cấy không bịa: REL-01 (gửi trùng tin nhắn do webhook redelivery), ERR-01 (Graph API 10/551), CFG-01 (env sai khi deploy) — đều là sự cố sản xuất đã xảy ra.

3.3 · Ba tool

grep · read_file · list_files — ba hàm Python thường. SDK đọc docstring để tự sinh JSON schema, nên docstring ở đây là prompt, không phải ghi chú.

Vì sao không embedding/vector search? Bug không nằm ở chỗ “giống câu hỏi về mặt ngữ nghĩa”. grep 'createHmac' ra chính xác 100%; embedding chỉ ra thứ na ná. Đã đo: #1234 vs #5678 ≈ 0.98 cosine — embedding mù với định danh chính xác.

        observation = TOOLS[fc.name](**dict(fc.args))
        response_parts.append(types.Part.from_function_response(
            name=fc.name, response={"result": observation}))

    contents.append(types.Content(role="user", parts=response_parts))
ReAct = Reasoning + Acting. Đúng vòng lặp con người làm khi đọc code lạ: nghĩ → grep → đọc → nghĩ → mở file → đọc → kết luận. Chỉ thay bước “nghĩ” bằng LLM. MAX_STEPS = 10 đến từ quan sát, không từ cảm tính: ban đầu 6, đo thấy guardrail ăn ~1 bước và điều tra bù mất 2–3 bước nữa nên 6 chết non giữa chừng.

3.5 · validate_report — cái cổng

agent.py:345

def validate_report(args: dict, tools_called: set) -> str:
    if NO_VALIDATOR:                       # arm ablation X6
        return ""
    if "read_file" not in tools_called:    # chua doc code thi cam ket luan
        return "TU CHOI: ban chua read_file file nao..."

    problems = []
    for i, f in enumerate(args.get("findings", [])):
        rel  = str(f.get("file", ""))
        path = os.path.join(CODEBASE_DIR, rel)
        if not os.path.isfile(path):                    # 1. file co that?
            problems.append(f"...file khong ton tai"); continue

        lines = open(path, encoding="utf-8", errors="ignore").read().splitlines()
        line_no = int(f.get("line", 0))
        if not (1 <= line_no <= len(lines)):            # 2. dong co that?
            problems.append(f"...file chi co {len(lines)} dong"); continue

        first  = (str(f.get("evidence", "")).splitlines() or [""])[0]
        ev     = " ".join(first.split())                # chuan hoa khoang trang
        actual = " ".join(lines[line_no - 1].split())
        if not ev or ev not in actual:                  # 3. khop NGUYEN VAN?
            problems.append("...evidence KHONG khop noi dung that cua dong")

        if f.get("evidence_type") == "code" and rel.endswith(".md"):
            problems.append("...file .md ma khai evidence_type='code'")   # 4.

    return ("TU CHOI bao cao - sua roi nop lai:\n" + "\n".join(problems[:10])
            if problems else "")
Nguyên tắc trung tâm của cả dự án: luật nào kiểm được bằng code thì không nhờ prompt giữ. Ban đầu luật này nằm trong prompt (“hãy trích dẫn chính xác”) — model quên. Chuyển xuống code thì nó không thể quên, vì code chặn chứ không khuyên.
Giới hạn đã đo: cổng chỉ kiểm được hình thức. Một lượt chạy nộp 75 finding, trong đó 70 cái cùng loại trong một file, trên bản SẠCH — và qua hết, vì mỗi dòng có thật và mỗi trích dẫn khớp. Cổng bảo đảm trích dẫn có thật; không bảo đảm finding có nghĩa.

Phần trên là cái auditor. Phần này là thứ khiến nó khác một script cuối tuần.

repo that -> cay 15 loi (moi loi 1 commit, message nguy trang)

          -> finding xuat hien o >=2/3 luot SACH = nhieu nen -> TRU DI

4.1 · Luật khớp

benchmark/score_benchmark.py:63

LINE_TOLERANCE = 5

def same_location_and_category(left: dict, right: dict) -> bool:
    if left["file"] != right["file"] or left["category"] != right["category"]:
        return False
    if left["line"] is None or right["line"] is None:
        return False
    return abs(left["line"] - right["line"]) <= LINE_TOLERANCE
Vì sao ±5 dòng? Agent trỏ dòng 270 trong khi lỗi ở 268 thì vẫn là tìm ra — bắt đúng tuyệt đối là đo trí nhớ số học, không đo năng lực tìm lỗi. Nhưng ±50 thì thành cho không.

4.2 · Phép trừ — trái tim của phép đo

benchmark/score_benchmark.py:86

def build_clean_consensus(clean_trials: list[list[dict]]) -> list[dict]:
    """Findings xuat hien o DA SO TUYET DOI cac luot sach = nhieu nen."""
    if len(clean_trials) < 3:
        raise ValueError("Can it nhat 3 clean trials de tao majority baseline.")
    threshold = len(clean_trials) // 2 + 1        # 3 luot -> can >= 2

    consensus = []
    for candidate in candidates:
        present = sum(1 for trial in clean_trials
                        if any(same_location_and_category(candidate, item)
                               for item in trial))
        if present >= threshold:
            consensus.append(candidate)
    return consensus

Không có bản sạch, dự án đã tự tin báo cáo một phát hiện không hề tồn tại.

Bốn phát hiện

  1. Gradient độ khó chưa từng đảo ở bất kỳ arm nào: de 100% → vua 47% → kho 39%. Agent bắt tốt lỗi grep ra được, sụp ở lỗi ngữ nghĩa liên thủ tục. Đây là kết luận về bài toán, không về một model.
  2. Harness ba tool đạt ngang agent thương mại — cách 2,3 điểm ở 1/4 chi phí, và bắt được SEED-REL-01 mà Claude Code trượt cả 3 lượt (union 9/14 vs 8/14).
  3. Precision đạt đỉnh ở model tầm trung (61.1%) rồi tụt ở model mạnh nhất (53.8%). Model mạnh hơn tìm được nhiều hơn nhưng ồn hơn. Không đơn điệu.
  4. Năm lỗi không arm nào bắt được. Hai trong số đó gắn nhãn vua chứ không phải kho — chúng kháng vì đòi phát hiện sự vắng mặt (thứ lẽ ra phải có mà không có). Một nhánh riêng trong bảng phân loại thất bại.

Thí nghiệm tự bác bỏ (X6)

Dự án từng tuyên bố “harness quyết định precision”, kèm lời tự nhận là chưa có bằng chứng. Thí nghiệm kiểm nó: tắt cổng, giữ nguyên mọi thứ khác. Ngưỡng đăng ký trước khi chạy: tụt ≥10 điểm thì claim thành đo được.

Kết quả: hiệu ứng 6,8 điểm — nhưng lượt đối chứng chạy lại cho thấy hai lần chạy của cùng một hành vi code lệch 10,7 điểm precision. Hiệu ứng nằm trong dải nhiễu → không được tuyên bố. Ngưỡng không sửa sau khi thấy dữ liệu; claim bị rút xuống.

Phép đo duy nhất sạch nhiễu là phép đếm cơ học: tỉ lệ finding trỏ vào thứ không tồn tại đi từ 5.2% (tắt cổng) về 0.0% (bật cổng). Cách nói đúng từ đó: cổng là bảo đảm về tính có thật của trích dẫn, không phải máy nâng precision.

Ba thứ chuyển nguyên vẹn, không phải viết lại: (1) golden set — đáp án biết trước; (2) differential sạch-vs-bẩn — chạy trên luồng không có gì bất thường để đo sàn nhiễu rồi trừ đi; (3) đăng ký giả thuyết trước khi chạy kèm luật bác bỏ. Ba thứ này không phụ thuộc miền.

Và một chi tiết thị trường: cây thước độc lập thì thị trường ở Việt Nam mỏng — đừng bán nó như sản phẩm riêng. Giá trị của nó là (a) bằng chứng năng lực, (b) bộ máy dùng lại cho câu hỏi kế tiếp: agent có ở trong quyền của nó không?
